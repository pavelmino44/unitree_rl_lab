# Go1 T3 v6: ограничения Safety Block и запас скорости

Обновление для **v5 с startup-, ground- и visual-fix**, на которой уже началась ходьба. Накладывается на текущую установку; v3 напрямую не поддерживается. Физические свойства MJCF, массы, инерции, коллизии, приводы и визуальные меши этот пакет не меняет.

## Что сверено с актуальным ТЗ

Прочитан репозиторий организаторов [Urika000/go1-simulator-public](https://github.com/Urika000/go1-simulator-public/tree/9de879c0a2e2e92220bd88d3613171ac08c2ba7a), commit `9de879c0a2e2e92220bd88d3613171ac08c2ba7a` от 21.11.2026, и отдельный документ [ТЗ T3](https://github.com/Urika000/go1-simulator-public/blob/9de879c0a2e2e92220bd88d3613171ac08c2ba7a/docs/parts_of_tz/ТЗ_T3.pdf). Реализация Safety Block взята именно из приложенного `hack_sol-main (1).zip`; её численные модули включены побайтно без изменения алгоритма. Их хеши приведены в `SOURCE_PROVENANCE.json` внутри пакета.

Актуальный T3: заявленная `preferred_speed_mps` от **0,1 до 0,6 м/с**, постоянная команда вперёд, y=0 и yaw=0. Десять независимых эпизодов, каждый с пересозданием контейнеров; прогрев 1,5 с, затем до 90 с на 3 м. Падение: высота ниже 0,16 м либо |roll|/|pitch| больше 50° непрерывно более 0,5 с. В локальном оценщике эпизоды сбрасываются внутри Isaac, поэтому он не заменяет официальный запуск.

В `hack_sol` нет обрезки скорости корпуса до 0,6 м/с. Safety Block ограничивает суставные команды, а при самоколлизии или превышении расчётного момента отклоняет **всю** команду и продолжает публиковать предыдущую принятую. Это действительно может уменьшить фактическую скорость, но увеличение максимальной команды само по себе не гарантирует компенсацию.

## Изменения действий

Порядок суставов сохранён: FR, FL, RR, RL; hip, thigh, calf. Actor по-прежнему имеет 225 входов и 12 выходов. Преобразование выхода сети: `q_requested = offset + scale * action`, где hip scale=0,15, thigh/calf scale=0,35. Номинальная поза прежняя: правый hip −0,1, левый +0,1, thigh 0,85, calf −1,7 рад.

| Ограничение | До v6 | В v6 |
|---|---|---|
| Выход actor перед масштабированием | ±1 | Дополнительная обрезка выключена |
| Hip target, рад | Справа [−0,32; −0,03], слева [0,03; 0,32] | [−0,863; 0,863] на всех ногах |
| Thigh target, рад | [0,05; 2,25] | [−0,686; 4,501] |
| Calf target, рад | [−2,60; −1,00] | [−2,818; −0,888] |
| Изменение принятого target | 4,5° за команду | До 5° за команду |
| Превышение расчётного PD-момента | Только насыщение актуатора | Дополнительно отклоняется вся команда |
| Самоколлизия целевого перехода | Не проверялась фильтром | Точная проверка при оценке; опциональна в PPO |

Раньше одновременная обрезка raw action ещё сильнее сужала доступные углы: thigh до [0,50; 1,20], calf до [−2,05; −1,35] рад. Теперь сеть может выйти за эти пределы; ограничения T2 при этом действуют. Для float32 оставлен только численный запас **1e−6 рад** у границ и 5-градусного шага. Это примерно 0,000057°, а не дополнительное ограничение позы.

Лимиты моторного момента: hip/thigh 23,7 Н·м, calf 35,55 Н·м. Фильтр проверяет `kp*(q_target-q_measured) - kd*dq_measured` при желаемых dq=0 и feedforward tau=0. Используются фактические настроенные gains артикуляции: в v5 kp=100, servo kd=0. Пассивное демпфирование MJCF не является kd в LowCmd и не включается в этот расчёт.

При отклонении `last_safe_q` не продвигается. После reset опорной командой становится измеренная поза, как при первом LowState в SafetyNode. Политика работает на 50 Гц. Таймер Safety Block на 100 Гц только повторяет принятую команду; он не даёт второго шага 5° между двумя публикациями политики. Реальные ROS задержки, timeout и начальная hold-команда с kp=30/kd=0,5 в Isaac не моделируются.

## Режимы проверки

По выбранному тобой варианту PPO сохраняет батчевые GPU-проверки конечности, углов, шага и момента. `collision_check="none"` означает, что полный перебор промежуточных целевых поз на CPU выключен. Физические самоколлизии в PhysX остаются включены, но они не заменяют отказ Safety Block по целевой траектории.

Оценщик `evaluate_go1_t3.py` по умолчанию включает `collision_check="mujoco"`: ровно тот же checker, та же модель и CSV из 655 проверяемых пар, шаг интерполяции 0,1°, запрет проникновения более 1 мм. На этой машине безопасный переход с максимальным изменением 5° занимал около 1,4 мс на одну среду (100 последовательных запросов). Это не оценка производительности твоего ноутбука; полный CPU-перебор в тысячах сред может сильно замедлить PPO.

Локальная проверка воспроизводит численную фильтрацию **суставных targets**; официальная проверка с ROS, очередями сообщений, LowState и MuJoCo-динамикой всё равно необходима.

## Скорость и curriculum

Максимальный продольный диапазон обучения расширен с ±0,6 до **±0,7 м/с**. Начало ±0,06, шаг curriculum 0,06 м/с, критерий награды и период проверки сохранены. Поперечный диапазон остаётся до ±0,24 м/с, yaw до ±1 рад/с. Так запас скорости не ускоряет начальные уровни curriculum.

В `ping` и `/cmd_vel` для зачётного решения по-прежнему допустимо максимум **0,6 м/с**. Не нужно автоматически умножать команду Judge на 0,7/0,6. Обучение на 0,7 создаёт запас возможностей, а способность держать 0,6 после фильтра проверяется отдельно. Оценщик намеренно принимает только скорости из разрешённого ТЗ диапазона.

Все награды и их веса, включая `undesired_contacts`, сохранены. Go2 и общие MDP-функции этот патч не меняет. В общем экспортёре добавлен только необязательный hook действия Go1: лимиты сохраняются без округления. Иначе штатные три значащие цифры превращали бы 5° в 0,0873 рад, что чуть превышает предел; мог округлиться и calf min −2,818. Для обычного действия Go2 результат экспорта проверен на побайтное совпадение с прежним.

## Установка

Сохрани checkpoint текущего запуска и закрой Isaac перед применением. Распакуй `go1_t3_safety_v6.zip` в `~/Downloads`:

```bash
python3 ~/Downloads/go1_t3_safety_v6/install.py \
  --repo ~/unitree-go2-rl/unitree_rl_lab --check

python3 ~/Downloads/go1_t3_safety_v6/install.py \
  --repo ~/unitree-go2-rl/unitree_rl_lab
```

Установщик проверяет хеши исходной физики v5 и изменяемых файлов, делает резервные копии в `go1_safety_backups`, поддерживает повторный запуск. Если у тебя есть дополнительные локальные правки в этих файлах, остановится до первой записи; сравни их с `files/` пакета и перенеси нужные изменения вручную. Не заменяй всю папку `unitree_rl_lab` содержимым архива.

Полная проверка targets требует MuJoCo в том же Python-окружении, что и Isaac. Для обычного быстрого PPO новый Python-пакет не нужен. Версия соответствует Dockerfile приложенного `hack_sol`:

```bash
conda activate env_isaaclab
python -m pip install 'mujoco==3.3.7'
cd ~/unitree-go2-rl/unitree_rl_lab
python -m unittest discover -s tests -p 'test_go1_safety.py' -v
```

## Запуск

Для чистого сравнения рекомендую **новое обучение**: изменилась функция применения действий, а у текущего checkpoint std уже около 0,06. Размер сети прежний, старые веса загружаются, но продолжение с прежним оптимизатором и низким exploration может плохо исследовать расширенный диапазон. Сохрани старый запуск как baseline.

```bash
python scripts/rsl_rl/train.py \
  --task Unitree-Go1-T3-Flat --num_envs 1000 --headless \
  --run_name t3_safety_v6
```

При создании среды ожидается строка:

```text
[GO1 ACTION SAFETY] raw_clip=disabled; target_step=5deg max; bounds=T2; torque_reject=True; collision_check=none
```

Проверка сохранённого checkpoint на максимальной зачётной команде, **с полной проверкой targets по Safety Block**:

```bash
python scripts/project/evaluate_go1_t3.py \
  --checkpoint logs/rsl_rl/unitree_go1_t3_flat/ИМЯ_ЗАПУСКА/model_1000.pt \
  --episodes 10 --speed 0.6 --collision-check mujoco --headless \
  --output logs/go1_t3_eval_v6_060.csv
```

Вместо `ИМЯ_ЗАПУСКА` и номера checkpoint подставь свой путь. Разумно также проверить 0,3 и 0,45. Для просмотра обычным `play.py` с полным checker:

```bash
python scripts/rsl_rl/play.py \
  --task Unitree-Go1-T3-Flat --num_envs 1 \
  --checkpoint logs/rsl_rl/unitree_go1_t3_flat/ИМЯ_ЗАПУСКА/model_1000.pt \
  env.actions.JointPositionAction.collision_check=mujoco
```

Play сохраняет свою фиксированную команду 0,3 м/с. Для изоляции влияния проверки можно повторить оценку с `--collision-check none` и другим CSV. Такой результат будет приближённым и не подтверждает прохождение T2 Safety Block. Для небольшого отдельного эксперимента полные CPU-проверки можно включить в обучение аналогичным Hydra-параметром `env.actions.JointPositionAction.collision_check=mujoco`.

## Новые метрики

В обучении они находятся под `Metrics/base_velocity/`, в CSV оценки идут без этого префикса:

| Метрика | Значение |
|---|---|
| `safety_bound_clip` | Средняя доля суставов команды, обрезанных по угловым границам |
| `safety_step_clip` | Средняя доля суставов, ограниченных по шагу target |
| `safety_nonfinite_reject` | Доля целиком отклонённых команд с NaN/Inf |
| `safety_torque_reject` | Доля целиком отклонённых команд по моторному моменту |
| `safety_collision_reject` | Доля команд, отклонённых checker самоколлизий |
| `safety_accepted` | Доля принятых команд |
| `safety_exact_collision_check` | 1 — точный CPU checker включён; 0 — выключен |

Ноль `safety_collision_reject` при `safety_exact_collision_check=0` не говорит об отсутствии запрещённых переходов. Все доли усредняются по шагам эпизода. В CSV дополнительно есть `mean_forward_mps`: фактический прогресс вперёд, делённый на зачётное время. Знаковое среднее vx всех обучающих сред не измеряет достижение максимальной скорости из-за разнонаправленных команд.

Высокий `safety_step_clip` при небольшой доле отказов не обязательно означает ошибку: фильтр может регулярно сглаживать быстрые изменения. Если `safety_torque_reject` или `safety_collision_reject` велики, запас максимальной команды не устранит причину: робот часто остаётся на предыдущем target. Сравни фиксированную команду 0,6 с включённым и выключенным collision checker.

## Проверки пакета

Пройдены 45 CPU-проверок без пропусков: сравнение с функциями приложенного Safety Block на 4096 наборах, удержание всей команды после отказа одного мотора, NaN/Inf, шаг 5°, сброс по измеренной позе, полный checker/655 пар, начальная стойка и реально коллидирующая конфигурация, промежуточные точки перехода, экспорт точных чисел, сохранение наград Go2 и условий curriculum, а также прежние проверки USD/MJCF/старта/земли. Для двух lifecycle-проверок использован исходный EventManager закреплённого Isaac Lab. Статическая проверка ошибок Python пройдена.

Реальный Isaac Sim, GPU-rollout, ROS и обучение здесь не запускались. Эти результаты подтверждают конфигурацию и численные правила фильтра, но не качество походки и не успешное прохождение официальных эпизодов.
