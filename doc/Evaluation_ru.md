# Оценка политики

Фиксированные воспроизводимые тесты обученной политики локомоции Go2:
- набор сценариев: ровная земля, лестницы, ямы, склоны, случайные блоки, ходьба боком и назад, разворот на месте, разгон и торможение;
- метрики по эпизоду, по сценарию и по всему прогону;
- просмотрщик с графиками.

| Файл | Назначение |
|---|---|
| `scripts/rsl_rl/evaluate.py` | Запускает сценарии и пишет JSON-отчёт |
| `scripts/rsl_rl/eval_gui.py` | Окно настроек (`evaluate.py --gui`) |
| `scripts/rsl_rl/eval_report.py` | Просмотр отчёта (открывается автоматически или отдельно) |
| `.../robots/go2/eval_scenarios.py` | Описание сценариев |
| `.../robots/go2/velocity_env_cfg.py` | `RobotEvalEnvCfg`: общие настройки оценки для всех сценариев |

Всё запускается из корня `unitree_rl_lab` в conda-окружении Isaac Lab. Для `eval_report.py` и GUI также нужны
`matplotlib` и `tkinter`.

## Быстрый старт

```bash
# окно настроек
python scripts/rsl_rl/evaluate.py --gui

# все сценарии, без окна симулятора
python scripts/rsl_rl/evaluate.py --headless --scenarios all --episodes 3

# открыть сохранённый отчёт ещё раз
python scripts/rsl_rl/eval_report.py logs/rsl_rl/<experiment>/<run>/eval/eval_model_XXXX_<time>.json

# или через unitree_rl_lab.sh с теми же аргументами
./unitree_rl_lab.sh -e
```

## evaluate.py

```bash
python scripts/rsl_rl/evaluate.py [--gui] [--task TASK] [--scenarios LIST] [--episodes N] [--eval_seed LIST]
                                  [--speed V] [--checkpoint PATH | --load_run RUN] [--output PATH]
                                  [--headless | --real-time] [--device DEV] [...]

./unitree_rl_lab.sh -e [--gui] [--task TASK] [--scenarios LIST] [--episodes N] [--eval_seed LIST]
                       [--speed V] [--checkpoint PATH | --load_run RUN] [--output PATH]
                       [--headless | --real-time] [--device DEV] [...]
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--gui` | | Открыть окно настроек; все остальные параметры задаются там |
| `--task` | `Unitree-Go2-Velocity` | Задача gym с `eval_env_cfg_entry_point` |
| `--scenarios` | `all` | Имена или glob-маски через запятую; `rough` = `rough_*`, `all` = все сценарии |
| `--episodes` | `5` | Эпизодов на сценарий **и** сид |
| `--eval_seed` | `42` | Сид или список через запятую (`42,43,44`); эпизоды всех сидов объединяются |
| `--speed` | из сценария | Заданная скорость в м/с для сценариев ходьбы (игнорируется `flat_turn_360`, `flat_max_speed`) |
| `--checkpoint` | | Файл модели (`model_XXXX.pt`) |
| `--load_run` | последний запуск | Папка запуска в `logs/rsl_rl/<experiment>/`, если чекпоинт не задан |
| `--output` | `<папка чекпоинта>/eval/eval_<model>_<time>.json` | Путь JSON-отчёта |
| `--headless` | | Без окна симулятора (быстро) |
| `--real-time` | | Окно симулятора в реальном времени |
| `--no_contact_termination` | | Касание базой не завершает эпизод (чтобы увидеть все касания) |
| `--record_dt` | `0.1` | Шаг (с) временных рядов в отчёте |
| `--no_report` | | Не открывать просмотрщик в конце |
| `--report_save` | | Дополнительно сохранить все графики в PNG в эту папку |
| `--num_envs` | `1` | Параллельные копии одного сценария |
| `--device`, `--disable_fabric` | | Параметры Isaac Lab |

Каждая пара (сценарий, сид) запускается в отдельном процессе Isaac Sim. Родительский процесс собирает
результаты, печатает таблицы, пишет один JSON-отчёт и открывает просмотрщик. Glob-маски берите в кавычки:
`--scenarios "rough_pyramid_stairs_*cm,flat*"`.

**Сиды.** Политика на инференсе детерминирована, и ровная земля, лестницы и склоны тоже: повторные эпизоды
на одном сиде почти одинаковы. Сид меняет раскладку случайных террейнов (`rough_boxes_*`,
`rough_random_rough`), для них используйте несколько сидов.

## GUI

`python scripts/rsl_rl/evaluate.py --gui`

- **Scenarios.** Список с мультивыбором, фильтр (подстрока или glob), быстрые фильтры (flat, stairs, slopes,
  boxes). При наведении на имя показывается описание сценария. *Refresh list* перечитывает сценарии после
  изменения `eval_scenarios.py`: запускается короткий headless Isaac Sim, а список кэшируется в
  `~/.cache/unitree_rl_lab/eval_catalog.json`.
- **Run settings.** Те же параметры, что и в командной строке. В строке *Equivalent command* видна команда,
  которая будет выполнена; *Copy* копирует её в буфер обмена.
- **Конфигурации.** *Save* / *Load* сохраняют и загружают все настройки в JSON (папка по умолчанию
  `scripts/rsl_rl/eval_configs/`). Последние настройки восстанавливаются при следующем запуске (`_last.json`).
- *Run* закрывает окно, прогон продолжается в терминале.

## Просмотр отчёта

```bash
python scripts/rsl_rl/eval_report.py REPORT.json [--scenarios LIST] [--no_overall] [--no_scenarios]
                                     [--no_episodes] [--max_windows N] [--save DIR] [--no_show] [--dpi D]
```

| Окно | Содержимое |
|---|---|
| Весь прогон | Исходы, слежение за скоростью и контакты корпуса по сценариям; успех в зависимости от высоты ступени, угла склона и сложности блоков; сводка и самые слабые сценарии |
| Сценарий | Средние по эпизодам вдоль трассы (или по времени / углу поворота): скорость и команда, где корпус касался поверхности, исход каждого эпизода, ошибка курса и боковое отклонение, наклон и мощность |
| Эпизод | Скорость от времени с командой, таймлайн контактов (база / голова / ноги), прогресс, ошибка курса, наклон и боковое отклонение, все числа |

Одновременно открывается не больше `--max_windows` (40) окон; `--save DIR --no_show` сохраняет все графики в
PNG. Без дисплея графики сохраняются рядом с отчётом. Окна масштабируются под экран (`--dpi` для ручной
настройки).

## Сценарии

Во всех сценариях:
- один робот, без доменной рандомизации, шума наблюдений и curriculum;
- робот появляется на ровной земле в 0,7 м перед препятствием, курс удерживается обратной связью по скорости поворота;
- эпизод заканчивается на линии цели;
- пирамиды и ямы проходятся целиком (подъём **и** спуск).

Сценарии `rough_*` берут террейн из `ROUGH_TERRAINS_CFG`, набора террейнов обучения.

| Сценарий | Задача |
|---|---|
| `flat` | 6 м вперёд, 0,5 м/с |
| `flat_backward` | 6 м назад, 0,5 м/с |
| `flat_strafe_right`, `flat_strafe_left` | 6 м боком, 0,3 м/с, корпус смотрит вперёд |
| `flat_turn_360` | Полный оборот на месте, 0,8 рад/с |
| `flat_max_speed` | Разгон до максимальной скорости диапазона обучения, команда 0 на 6-й секунде; успех = не упал и остановился |
| `rough_pyramid_stairs_<N>cm` | Пирамидная лестница, высота ступени N = 5, 10…20 см |
| `rough_pyramid_stairs_inv_<N>cm` | Яма (перевёрнутая пирамида), те же высоты |
| `rough_pyramid_stairs[_inv]_d100` | Лестница / яма со сложностью ROUGH 1.0 |
| `rough_boxes_d25/50/75/100` | Случайные блоки, сложность 25…100 % |
| `rough_hf_pyramid_slope_<A>deg` | Пирамидный склон, A = 10…45° |
| `rough_hf_pyramid_slope[_inv]_d50/_d100` | Склон / перевёрнутый склон со сложностью ROUGH |
| `rough_random_rough` | Равномерный шум высоты |
| `slope_up_0p2`, `slope_up_0p4` | Склоны, заданные вручную, уклон (подъём/пролёт) 0,2 и 0,4 |

Чтобы добавить сценарий, добавьте запись в `EVAL_SCENARIOS` в конце `eval_scenarios.py`.

## Метрики

Значения по каждому эпизоду лежат в JSON-отчёте. Таблицы и просмотрщик показывают средние (и худшие)
значения по сценарию и по прогону.

### Задача

| Метрика | Значение |
|---|---|
| `success` | Пересечена линия цели (дальняя сторона пирамиды/ямы, полный оборот на 360°, для `flat_max_speed`: не упал и остановился) |
| `midpoint` | Достигнута вершина пирамиды, дно ямы или центр блоков |
| `falls` | Эпизод завершён терминацией (`bad_orientation`, `base_contact`) до цели |
| `timeouts` | Ни цели, ни падения до лимита времени; обычно робот застрял |
| `t_goal` | Время до цели (успешные эпизоды) |
| `progress` | Лучшее продвижение вдоль трассы (м), для разворота — угол (град) |
| `end reasons` | Какая терминация завершила каждый эпизод |

### Слежение за командой и траектория

| Метрика | Значение |
|---|---|
| `speed` | Средняя скорость вдоль заданного направления (положительная, если робот движется куда нужно) |
| `vel err xy` | Среднее расстояние между заданной и измеренной скоростью в плоскости, м/с |
| `vel err yaw` | Средняя ошибка скорости поворота, рад/с |
| `yaw err` (ошибка курса) | Наибольшее отклонение курса от курса на старте, град (для разворота не считается) |
| `lateral` | Наибольшее боковое отклонение от линии старта, м (для разворота — снос корпуса от точки старта) |

### Контакты корпуса

Касания тела робота (не стоп) с окружением. Порог — порог силы из терминации обучения (1 Н):

| Часть | Тела | В обучении |
|---|---|---|
| база | `base` | завершает эпизод (`base_contact`) |
| голова | `Head_.*` | только штраф (`undesired_contacts`) |
| ноги | `*_hip`, `*_thigh`, `*_calf` | только штраф (`undesired_contacts`) |

**trunk** (корпус) = база или голова. Для корпуса и ног считаются:
- число касаний за эпизод (касания ближе 0,1 с считаются одним);
- доля эпизодов с касанием;
- время в контакте;
- момент первого касания;
- максимальная сила.

По каждой части ещё отдельные счётчики и таймлайн в окне эпизода.

### Разгон и торможение (`flat_max_speed`)

| Метрика | Значение |
|---|---|
| `peak` | Наибольшая скорость до команды остановки |
| `t to 90%` | Время до 90 % заданной скорости |
| `at brake` | Скорость в момент команды остановки |
| `stop time`, `stop dist` | Время и путь до момента, когда \|v\| < 0,1 м/с держится 0,5 с |
| `lowest` | Наименьшая скорость после команды остановки (отрицательная = робота отбросило назад) |
| `stopped` | Доля эпизодов, в которых робот остановился |

### Устойчивость, затраты, плавность

| Метрика | Значение |
|---|---|
| `tilt` | Угол между вертикальной осью корпуса и гравитацией (крен и тангаж вместе), среднее и максимум, град |
| `power` | Средняя механическая мощность Σ\|τ·q̇\|, Вт |
| `CoT` | Удельные затраты на перемещение E / (m·g·d): энергия на единицу пути, меньше — экономичнее |
| `action rate` | Среднее \|a_t − a_t−1\|: насколько резко меняются действия |
| `joint acc` | Средняя норма ускорений суставов |
| `reward`, `reward terms /s` | Награда обучения за эпизод; каждая составляющая в секунду, сопоставима с `Episode_Reward/<term>` в логах обучения |

## Как читать результаты

1. **Кривые по сложности** в окне всего прогона. Строка «passed up to N cm / deg» (успех ≥ 80 % на всех
   уровнях до N) — самое компактное описание того, что умеет политика. Сравнивайте её между чекпоинтами.
2. **Ровная земля** (`flat*`). Должно быть 100 % успеха и около 100 % слежения за скоростью; это проверка на
   регрессию.
3. **Самые слабые сценарии.** Откройте их окна: графики вдоль трассы показывают, *где* политика ошибается.
4. **Затраты и плавность** помогают выбрать между чекпоинтами с одинаковыми возможностями.

| Что видно | Вероятная причина |
|---|---|
| `midpoint` высокий, `success` низкий | Поднимается, но падает на спуске |
| Касания головой на лестнице | Робот опирается носом на следующую ступень (касание головой не завершает эпизод в обучении) |
| Касания ногами на кромках ступеней | Ноги поднимаются недостаточно высоко |
| Много таймаутов, малый прогресс | Застревает перед препятствием |
| Ошибка курса растёт на препятствиях | Несимметричная походка; сравните с `flat_strafe_*` и `flat_turn_360` |
| Отрицательный `lowest` после остановки | Резкое торможение |

Используйте одинаковый набор сценариев, сидов и число эпизодов для всех сравниваемых чекпоинтов (сохраните его
как конфигурацию GUI). Разница в один эпизод из пяти — в пределах шума.
